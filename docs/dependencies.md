# Dependencies

- After editing any dependency manifest (`package.json`, `pnpm-workspace.yaml`, `.npmrc`), run `pnpm install` immediately.
- After a `rebase`, `merge`, or `stash pop` that changed dependency files (including `pnpm-lock.yaml`), run `pnpm install` before any validation command (`build`, `test`, `e2e`, `lint`) — stale `node_modules` produces failures that look like regressions.
- Commit the resulting `pnpm-lock.yaml` changes in the same branch. Never push dependency manifest changes without the matching `pnpm-lock.yaml` update.
- `@storybook/scripts` is intentionally a root-only `devDependency`: package-local Rslib configs resolve it from the root `node_modules`, keeping this private workspace package out of published package manifests.
- In `packages/*`, dependency type is a bundle-vs-external switch, not dev-vs-prod: `createRslibConfig` enables `output.autoExternal`, which externalizes `dependencies`, `optionalDependencies`, and `peerDependencies` while leaving `devDependencies` bundled; each package's self-reference is an explicit external. Some runtime imports (e.g. `slash`, `pretty-hrtime` in `storybook-builder-rsbuild`) sit in `devDependencies` deliberately so they get vendored into the bundle — "fixing" them into `dependencies` changes what is published. Check the factory's external policy before reclassifying a dependency.
- `peerDependencies` are hand-maintained: Renovate's global rule disables `peerDependencies` updates, except the `storybook` group in `.github/renovate.json5`, which bumps `dependencies`, `devDependencies`, and `peerDependencies` for `storybook` / `@storybook/**` together in one PR.
- Non-Storybook peer ranges (`@rsbuild/core`, `react`, `react-dom`) are deliberately **wider** than the matching `devDependencies`. Never narrow them: `pnpm check-dependency-version` only cross-checks that peer ranges agree between packages, so a narrowed range stays green while silently dropping supported consumers.
- The `storybook` peer is the exception and is not free-form: `scripts/check-dependency-version.mts` asserts every `packages/*` package's `peerDependencies.storybook` is byte-equal to the installed `@storybook/<renderer>`'s own `storybook` peer (a guard against two copies of `storybook` in the pnpm virtual store). Align it exactly on every storybook bump — even when that narrows it — and run `pnpm check-dependency-version` after the edit.
- Before hand-bumping a dependency, check `.github/renovate.json5`: `allowedVersions` rules cap some versions on purpose and `ignoreDeps` lists packages updated only by hand. The `react-16` cap (`<17.0.0`, keeping the React 16 regression sandbox on 16.x) and the `rstack` cap (a regex admitting only release/beta/rc versions, blocking canary tags) are explained only by their `groupName`. Treat an uncommented cap as deliberate — never lift one without asking.
