# Migration

This guide covers migrating an existing Storybook project from the **webpack5** or **Vite** framework to **Storybook Rsbuild** (e.g. `storybook-react-rsbuild`).

:::tip Using an AI coding agent?
Your agent can handle this migration automatically. Install the agent skills and ask it to migrate your project:

<PackageManagerTabs
  command="skills add rstackjs/agent-skills --skill storybook-rsbuild"
  dlx
/>

:::

:::info Storybook versions

Match your Storybook version to the correct storybook-rsbuild release:

| Storybook | Storybook Rsbuild |
| --------- | ----------------- |
| v11       | `^4`              |
| v10       | `^3`              |
| v9        | `^2`              |
| v8        | `^1`              |

:::

:::info React 18+
Storybook 11 removed the React legacy root API. Remove `legacyRootApi` from `framework.options`; React 18 or 19 is required.
:::

:::info Dropped peer versions
v4 drops support for legacy peer versions. Upgrade before you move to v4.

`@rsbuild/core` must resolve to <PeerRange name="@rsbuild/core" />. Rsbuild 1.x and Rspack 1.x are no longer supported; projects that need them stay on Storybook Rsbuild `^3`.

`react-native-web` must resolve to <PeerRange name="react-native-web" /> when you use the React Native Web framework; the previous floor was `0.19.0`.

`@modern-js/app-tools` must resolve to <PeerRange name="@modern-js/app-tools" /> when you use the Modern.js addon. Modern.js 2 is no longer supported, and `@modern-js/plugin-v2` is no longer a peer.

`@rslib/core` must resolve to <PeerRange name="@rslib/core" /> when you use the Rslib addon; 0.20 and 0.21 build against Rsbuild 2 pre-releases.

:::

:::info React builder docgen packages are optional peers
`react-docgen` and `react-docgen-typescript` are now optional peer dependencies of `storybook-react-rsbuild` and `storybook-react-native-web-rsbuild`, so projects on server-side docgen no longer install them, nor the Babel toolchain that `react-docgen` brings along. `typescript` is now a required peer dependency of the React, Vue 3, React Native Web, and Web Components frameworks.

Only projects whose `.storybook/main.ts` sets `features.docgenServer: false` are affected. Builder docgen loads these packages only when it runs; if one is missing, `storybook dev` and `storybook build` fail with the install command for your package manager. Add the packages for your `typescript.reactDocgen` mode to `devDependencies`:

| `typescript.reactDocgen`    | Add to devDependencies    |
| --------------------------- | ------------------------- |
| `'react-docgen'` (default)  | `react-docgen`            |
| `'react-docgen-typescript'` | `react-docgen-typescript` |

There is no plugin package to install for `react-docgen-typescript`: `storybook-react-rsbuild` ships its own plugin. In that mode `react-docgen` is optional and only documents JavaScript files; without it, JavaScript components get no props, and Storybook does not warn about that. Without a usable `typescript` (not installed, or TypeScript 7, which has no compiler API), `react-docgen-typescript` falls back to `react-docgen`.

Set `typescript.reactDocgen: false` to run without docgen, or better, remove `docgenServer: false` to use server-side docgen. Storybook does not add these packages when you upgrade.
:::

:::info `htmlLang` main-config option removed
`htmlLang` is no longer a main-config option, to match upstream Storybook, and the preview `<html>` element is always `lang="en"`. To set a language, use the `htmlLang` story parameter (`parameters.htmlLang`), which sets `lang` on the story root element (story view) or the embedded story canvas (docs view), not on the iframe `<html>`. Use `parameters.docs.lang` for the language of docs prose such as descriptions; Storybook's own UI stays English. Both parameters come from Storybook 11 ([storybook#35321](https://redirect.github.com/storybookjs/storybook/pull/35321)).
:::

## From Storybook Webpack5 Framework

If your `.storybook/main.ts` uses a webpack5 framework package (e.g. `@storybook/react-webpack5`, `@storybook/vue3-webpack5`), follow this section.

### 1. Replace packages

Uninstall the old webpack5 framework package, and install the Rsbuild equivalent along with `@rsbuild/core`.

For example, to migrate a React project:

<PackageManagerTabs command="install @rsbuild/core storybook-react-rsbuild -D" />

Then remove the old packages:

<PackageManagerTabs command="remove @storybook/builder-webpack5 @storybook/react-webpack5" />

The framework package (e.g. `storybook-react-rsbuild`) includes `storybook-builder-rsbuild` as a dependency — you do **not** need to install the builder separately.

#### Package mapping

| Old (webpack5)                       | New (Rsbuild)                      |
| ------------------------------------ | ---------------------------------- |
| `@storybook/react-webpack5`          | `storybook-react-rsbuild`          |
| `@storybook/vue3-webpack5`           | `storybook-vue3-rsbuild`           |
| `@storybook/html-webpack5`           | `storybook-html-rsbuild`           |
| `@storybook/web-components-webpack5` | `storybook-web-components-rsbuild` |

### 2. Update `.storybook/main.ts`

```ts twoslash title=".storybook/main.ts"
// @noErrors
// Before
// import type { StorybookConfig } from '@storybook/react-webpack5'
// After
import type { StorybookConfig } from 'storybook-react-rsbuild'

const config: StorybookConfig = {
  // Before: framework: '@storybook/react-webpack5',
  framework: 'storybook-react-rsbuild',
  stories: ['../src/**/*.stories.@(js|jsx|mjs|ts|tsx)'],
}

export default config
```

### 3. Convert `webpackFinal` to `rsbuildFinal`

:::warning Use `mergeRsbuildConfig` for modifications
Always use [`mergeRsbuildConfig`](https://rsbuild.rs/api/javascript-api/core#mergersbuildconfig) from `@rsbuild/core` to modify the config. Directly mutating properties like `config.tools.rspack = {...}` may not work because internal configs can be arrays of functions/objects, and direct assignment may be silently ignored.
:::

```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'
import { mergeRsbuildConfig } from '@rsbuild/core'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Before:
  // webpackFinal: async (config) => {
  //   config.resolve.alias['@components'] = path.resolve(__dirname, '../src/components')
  //   config.module.rules.push({ test: /\.svg$/, use: ['@svgr/webpack'] })
  //   return config
  // },

  // After:
  rsbuildFinal: async (config) => {
    return mergeRsbuildConfig(config, {
      resolve: {
        alias: {
          '@components': './src/components',
        },
      },
      // For SVG, use @rsbuild/plugin-svgr
    })
  },
}

export default config
```

:::tip Use relative paths in `resolve.alias`
Rsbuild resolves alias values relative to the project root. Use `'./src/components'`, not `path.resolve(__dirname, '../src/components')`. The relative form is shorter and avoids `__dirname` issues in ESM configs.
:::

### 4. Handle webpack-dependent addons

Some Storybook addons use `webpackFinal` internally. List them in `webpackAddons`. If an addon also provides UI or other preset hooks, keep it in `addons` too:

```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Regular addons (framework-agnostic)
  addons: ['@storybook/addon-docs', '@storybook/addon-onboarding'],
  // Addons that depend on webpack loaders/plugins
  webpackAddons: ['@storybook/addon-coverage'],
}

export default config
```

Only addons listed in `webpackAddons` have their `webpackFinal` run, and only that hook is applied. The returned config is merged into the Rspack config as is, which works because Rspack is compatible with webpack's loader/plugin API.

:::tip Common addons that need `webpackAddons`
A few addons hook `webpackFinal` internally and must be listed in `webpackAddons` (or be replaced with the Rsbuild-native equivalent):

- `@storybook/addon-styling-webpack` — global CSS / PostCSS / Sass / Less. Either route via `webpackAddons` or replace with [`@rsbuild/plugin-postcss`](https://rsbuild.rs/plugins/list/plugin-postcss), [`@rsbuild/plugin-sass`](https://rsbuild.rs/plugins/list/plugin-sass), or [`@rsbuild/plugin-less`](https://rsbuild.rs/plugins/list/plugin-less).
- `@storybook/addon-coverage` — collects test coverage; route via `webpackAddons`.

If an addon's name ends in `-webpack` or its docs mention `webpackFinal`, assume it needs this treatment. Silently dropping a webpack-only addon is a regression even if `storybook build` still passes.
:::

### 5. Convert common webpack patterns

| webpack pattern                    | Rsbuild equivalent                                                    |
| ---------------------------------- | --------------------------------------------------------------------- |
| `config.resolve.alias`             | `resolve.alias` in `rsbuildFinal`                                     |
| `config.resolve.extensions`        | `resolve.extensions` (Rsbuild has sensible defaults)                  |
| `config.module.rules` (loaders)    | `tools.rspack` or Rsbuild plugins                                     |
| `config.plugins` (webpack plugins) | `tools.rspack` for Rspack plugins                                     |
| `DefinePlugin`                     | `source.define`                                                       |
| `css-loader` / `style-loader`      | Built-in, use `tools.cssLoader` if customizing                        |
| `sass-loader`                      | [`@rsbuild/plugin-sass`](https://rsbuild.rs/plugins/list/plugin-sass) |
| `less-loader`                      | [`@rsbuild/plugin-less`](https://rsbuild.rs/plugins/list/plugin-less) |
| `file-loader` / `url-loader`       | Built-in asset modules                                                |
| SVGR                               | [`@rsbuild/plugin-svgr`](https://rsbuild.rs/plugins/list/plugin-svgr) |

:::tip Rspack plugin compatibility
Not all webpack plugins are compatible with Rspack. Check the [Rspack compatibility guide](https://rspack.rs/guide/compatibility/plugin) for details.
:::

## From Storybook Vite Framework

### 1. Replace packages

For example, to migrate a React project:

| Old (Vite)                       | New (Rsbuild)                      |
| -------------------------------- | ---------------------------------- |
| `@storybook/react-vite`          | `storybook-react-rsbuild`          |
| `@storybook/vue3-vite`           | `storybook-vue3-rsbuild`           |
| `@storybook/html-vite`           | `storybook-html-rsbuild`           |
| `@storybook/web-components-vite` | `storybook-web-components-rsbuild` |

### 2. Update `.storybook/main.ts`


```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'
import { mergeRsbuildConfig } from '@rsbuild/core'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Before:
  // viteFinal: async (config) => {
  //   config.resolve.alias['@'] = path.resolve(__dirname, '../src')
  //   return config
  // },

  // After:
  rsbuildFinal: async (config) => {
    return mergeRsbuildConfig(config, {
      resolve: {
        alias: {
          '@': './src',
        },
      },
    })
  },
}

```

:::tip Use relative paths in `resolve.alias`
Rsbuild resolves alias values relative to the project root. Use `'./src'`, not `path.resolve(__dirname, '../src')`. The relative form is shorter and avoids `__dirname` issues in ESM configs.
:::

### 4. Convert common Vite patterns

| Vite pattern              | Rsbuild equivalent                               |
| ------------------------- | ------------------------------------------------ |
| `resolve.alias`           | `resolve.alias` in `rsbuildFinal`                |
| `plugins: [react()]`      | Auto-configured by framework package             |
| `css.preprocessorOptions` | `@rsbuild/plugin-sass` or `@rsbuild/plugin-less` |
| `define`                  | `source.define`                                  |
| `server.proxy`            | `server.proxy`                                   |
| `build.target`            | `output.target`                                  |

:::tip Vite plugins are not compatible
Vite plugins cannot be used with Rsbuild. Find equivalent Rsbuild plugins at the [Rsbuild plugin list](https://rsbuild.rs/plugins/list/).
:::

## Verification

After migration, verify:

1. `npx storybook dev` starts without errors
2. All stories render correctly
3. HMR works (edit a component, see it update)
4. `npx storybook build` completes successfully
5. Addons function correctly (especially docs, controls, actions)

## Debugging

Enable Rsbuild debug mode to inspect the generated config:

```bash
DEBUG=rsbuild storybook dev
```

Check the CLI output to see where the Rsbuild and Rspack configs are written.
