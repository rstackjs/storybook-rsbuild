# 迁移

本指南介绍如何将现有的 Storybook 项目从 **webpack5** 或 **Vite** framework 迁移到 **Storybook Rsbuild**（例如 `storybook-react-rsbuild`）。

:::tip Using an AI coding agent?
你的 agent 可以自动完成此次迁移。安装 agent skills 并让它迁移你的项目：

<PackageManagerTabs
  command="skills add rstackjs/agent-skills --skill storybook-rsbuild"
  dlx
/>

:::

:::info Storybook versions

请将你的 Storybook 版本与对应的 storybook-rsbuild 版本匹配：

| Storybook | Storybook Rsbuild |
| --------- | ----------------- |
| v11       | `^4`              |
| v10       | `^3`              |
| v9        | `^2`              |
| v8        | `^1`              |

:::

:::info React 18+
Storybook 11 移除了 React legacy root API。请从 `framework.options` 中删除 `legacyRootApi`，并使用 React 18 或 19。
:::

:::info 不再支持的 peer 版本
v4 不再支持旧版 peer。升级到 v4 之前请先完成升级。

`@rsbuild/core` 必须解析到 <PeerRange name="@rsbuild/core" />。不再支持 Rsbuild 1.x 和 Rspack 1.x；仍需要这些版本的项目请继续使用 Storybook Rsbuild `^3`。

使用 React Native Web framework 时，`react-native-web` 必须解析到 <PeerRange name="react-native-web" />，此前的最低版本是 `0.19.0`。

使用 Modern.js addon 时，`@modern-js/app-tools` 必须解析到 <PeerRange name="@modern-js/app-tools" />。不再支持 Modern.js 2，也不再声明 `@modern-js/plugin-v2` peer。

使用 Rslib addon 时，`@rslib/core` 必须解析到 <PeerRange name="@rslib/core" />；0.20 和 0.21 基于 Rsbuild 2 的预发布版本构建。

:::

:::info React builder docgen 相关包变为可选 peer
`react-docgen` 和 `react-docgen-typescript` 现在是 `storybook-react-rsbuild` 与 `storybook-react-native-web-rsbuild` 的可选 peer dependency，因此使用 server-side docgen 的项目不再安装它们，也不会安装 `react-docgen` 带来的 Babel 工具链。`typescript` 现在是 React、Vue 3、React Native Web 和 Web Components 这几个 framework 的必需 peer dependency。

只有在 `.storybook/main.ts` 中设置了 `features.docgenServer: false` 的项目会受到影响。Builder docgen 只在运行时才会加载这些包；缺少任何一个包时，`storybook dev` 和 `storybook build` 会失败，并给出对应包管理器的安装命令。请按 `typescript.reactDocgen` 的模式，把需要的包加入 `devDependencies`：

| `typescript.reactDocgen`    | 需要加入 devDependencies  |
| --------------------------- | ------------------------- |
| `'react-docgen'`（默认）    | `react-docgen`            |
| `'react-docgen-typescript'` | `react-docgen-typescript` |

`react-docgen-typescript` 模式不需要额外安装 plugin 包：`storybook-react-rsbuild` 自带该 plugin。此模式下 `react-docgen` 是可选的，只用于解析 JavaScript 文件；缺少它时 JavaScript 组件不会有 props，且 Storybook 不会给出警告。当 `typescript` 不可用（未安装，或是没有 compiler API 的 TypeScript 7）时，`react-docgen-typescript` 会回退到 `react-docgen`。

可以设置 `typescript.reactDocgen: false` 来关闭 docgen；更推荐的做法是移除 `docgenServer: false`，改用 server-side docgen。升级时 Storybook 不会自动添加这些包。
:::

:::info `htmlLang` main 配置项已移除
为与上游 Storybook 保持一致，`htmlLang` 不再是 main 配置项，preview 的 `<html>` 元素固定为 `lang="en"`。如需设置语言，请使用 `htmlLang` story parameter（`parameters.htmlLang`）：它设置的是 story 根元素（story 视图）或内嵌 story canvas（docs 视图）的 `lang`，而不是 iframe `<html>` 的 `lang`。docs 正文（如描述）的语言请使用 `parameters.docs.lang`；Storybook 自身的界面仍为英文。这两个 parameter 自 Storybook 10.5 起提供（[storybook#35321](https://redirect.github.com/storybookjs/storybook/pull/35321)）。
:::

## 从 Storybook Webpack5 Framework 迁移

如果你的 `.storybook/main.ts` 使用了 webpack5 framework 包（例如 `@storybook/react-webpack5`、`@storybook/vue3-webpack5`），请按照本节操作。

### 1. 替换包

卸载旧的 webpack5 framework 包，并安装对应的 Rsbuild 版本以及 `@rsbuild/core`。

例如，迁移一个 React 项目：

<PackageManagerTabs command="install @rsbuild/core storybook-react-rsbuild -D" />

然后移除旧的包：

<PackageManagerTabs command="remove @storybook/builder-webpack5 @storybook/react-webpack5" />

framework 包（例如 `storybook-react-rsbuild`）已将 `storybook-builder-rsbuild` 作为依赖项包含在内——你**无需**单独安装 builder。

#### 包映射关系

| 旧（webpack5）                       | 新（Rsbuild）                      |
| ------------------------------------ | ---------------------------------- |
| `@storybook/react-webpack5`          | `storybook-react-rsbuild`          |
| `@storybook/vue3-webpack5`           | `storybook-vue3-rsbuild`           |
| `@storybook/html-webpack5`           | `storybook-html-rsbuild`           |
| `@storybook/web-components-webpack5` | `storybook-web-components-rsbuild` |

### 2. 更新 `.storybook/main.ts`

```ts twoslash title=".storybook/main.ts"
// @noErrors
// Before
// import type { StorybookConfig } from '@storybook/react-webpack5'
// After
import type { StorybookConfig } from 'storybook-react-rsbuild'

const config: StorybookConfig = {
  // Before: framework: '@storybook/react-webpack5',
  framework: 'storybook-react-rsbuild',
  stories: ['../src/**/*.stories.@(js|jsx|mjs|ts|tsx)'],
}

export default config
```

### 3. 将 `webpackFinal` 转换为 `rsbuildFinal`

:::warning Use `mergeRsbuildConfig` for modifications
请始终使用来自 `@rsbuild/core` 的 [`mergeRsbuildConfig`](https://rsbuild.rs/api/javascript-api/core#mergersbuildconfig) 来修改配置。直接修改 `config.tools.rspack = {...}` 这类属性可能不会生效，因为内部配置可能是由函数/对象组成的数组，直接赋值可能会被静默忽略。
:::

```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'
import { mergeRsbuildConfig } from '@rsbuild/core'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Before:
  // webpackFinal: async (config) => {
  //   config.resolve.alias['@components'] = path.resolve(__dirname, '../src/components')
  //   config.module.rules.push({ test: /\.svg$/, use: ['@svgr/webpack'] })
  //   return config
  // },

  // After:
  rsbuildFinal: async (config) => {
    return mergeRsbuildConfig(config, {
      resolve: {
        alias: {
          '@components': './src/components',
        },
      },
      // For SVG, use @rsbuild/plugin-svgr
    })
  },
}

export default config
```

:::tip Use relative paths in `resolve.alias`
Rsbuild 会相对于项目根目录解析 alias 值。请使用 `'./src/components'`，而不是 `path.resolve(__dirname, '../src/components')`。相对路径写法更简洁，并且能避免 ESM 配置中 `__dirname` 带来的问题。
:::

### 4. 处理依赖 webpack 的 addon

部分 Storybook addon 在内部使用了 `webpackFinal`。请把它们写进 `webpackAddons`；如果某个 addon 还提供 UI 或其他 preset 钩子，`addons` 中也要保留它：

```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Regular addons (framework-agnostic)
  addons: ['@storybook/addon-docs', '@storybook/addon-onboarding'],
  // Addons that depend on webpack loaders/plugins
  webpackAddons: ['@storybook/addon-coverage'],
}

export default config
```

只有写进 `webpackAddons` 的 addon 才会运行 `webpackFinal`，并且只会应用这一个钩子。返回的配置会原样合并进 Rspack 配置，这依赖于 Rspack 对 webpack loader/plugin API 的兼容。

:::tip Common addons that need `webpackAddons`
有一些 addon 在内部挂载了 `webpackFinal`，必须写进 `webpackAddons`（或替换为 Rsbuild 原生等价方案）：

- `@storybook/addon-styling-webpack` —— 全局 CSS / PostCSS / Sass / Less。可通过 `webpackAddons` 接入，或替换为 [`@rsbuild/plugin-postcss`](https://rsbuild.rs/plugins/list/plugin-postcss)、[`@rsbuild/plugin-sass`](https://rsbuild.rs/plugins/list/plugin-sass) 或 [`@rsbuild/plugin-less`](https://rsbuild.rs/plugins/list/plugin-less)。
- `@storybook/addon-coverage` —— 收集测试覆盖率；通过 `webpackAddons` 接入。

如果某个 addon 的名称以 `-webpack` 结尾，或其文档提到了 `webpackFinal`，则可以认为它需要这样处理。即使 `storybook build` 仍然通过，静默丢弃一个仅支持 webpack 的 addon 也是一种功能退化。
:::

### 5. 转换常见的 webpack 模式

| webpack 模式                        | Rsbuild 等价方案                                                      |
| ----------------------------------- | --------------------------------------------------------------------- |
| `config.resolve.alias`              | `rsbuildFinal` 中的 `resolve.alias`                                   |
| `config.resolve.extensions`         | `resolve.extensions`（Rsbuild 已有合理的默认值）                      |
| `config.module.rules`（loaders）    | `tools.rspack` 或 Rsbuild plugins                                     |
| `config.plugins`（webpack plugins） | 对于 Rspack plugins 使用 `tools.rspack`                               |
| `DefinePlugin`                      | `source.define`                                                       |
| `css-loader` / `style-loader`       | 内置支持，如需自定义可使用 `tools.cssLoader`                          |
| `sass-loader`                       | [`@rsbuild/plugin-sass`](https://rsbuild.rs/plugins/list/plugin-sass) |
| `less-loader`                       | [`@rsbuild/plugin-less`](https://rsbuild.rs/plugins/list/plugin-less) |
| `file-loader` / `url-loader`        | 内置 asset modules                                                    |
| SVGR                                | [`@rsbuild/plugin-svgr`](https://rsbuild.rs/plugins/list/plugin-svgr) |

:::tip Rspack plugin compatibility
并非所有 webpack plugin 都与 Rspack 兼容。详情请查阅 [Rspack 兼容性指南](https://rspack.rs/guide/compatibility/plugin)。
:::

## 从 Storybook Vite Framework 迁移

如果你的 `.storybook/main.ts` 使用了 Vite framework 包（例如 `@storybook/react-vite`、`@storybook/vue3-vite`），请按照本节操作。

### 1. 替换包

卸载旧的 Vite framework 包，并安装对应的 Rsbuild 版本以及 `@rsbuild/core`。

例如，迁移一个 React 项目：

<PackageManagerTabs command="install @rsbuild/core storybook-react-rsbuild -D" />

然后移除旧的包：

<PackageManagerTabs command="remove @storybook/builder-vite @storybook/react-vite" />

#### 包映射关系

| 旧（Vite）                       | 新（Rsbuild）                      |
| -------------------------------- | ---------------------------------- |
| `@storybook/react-vite`          | `storybook-react-rsbuild`          |
| `@storybook/vue3-vite`           | `storybook-vue3-rsbuild`           |
| `@storybook/html-vite`           | `storybook-html-rsbuild`           |
| `@storybook/web-components-vite` | `storybook-web-components-rsbuild` |

### 2. 更新 `.storybook/main.ts`

```ts twoslash title=".storybook/main.ts"
// @noErrors
// Before
// import type { StorybookConfig } from '@storybook/react-vite'
// After
import type { StorybookConfig } from 'storybook-react-rsbuild'

const config: StorybookConfig = {
  // Before: framework: '@storybook/react-vite',
  framework: 'storybook-react-rsbuild',
  stories: ['../src/**/*.stories.@(js|jsx|mjs|ts|tsx)'],
}

export default config
```

### 3. 将 `viteFinal` 转换为 `rsbuildFinal`

```ts twoslash title=".storybook/main.ts"
// @noErrors
import type { StorybookConfig } from 'storybook-react-rsbuild'
import { mergeRsbuildConfig } from '@rsbuild/core'

const config: StorybookConfig = {
  framework: 'storybook-react-rsbuild',
  stories: [],
  // Before:
  // viteFinal: async (config) => {
  //   config.resolve.alias['@'] = path.resolve(__dirname, '../src')
  //   return config
  // },

  // After:
  rsbuildFinal: async (config) => {
    return mergeRsbuildConfig(config, {
      resolve: {
        alias: {
          '@': './src',
        },
      },
    })
  },
}

export default config
```

:::tip Use relative paths in `resolve.alias`
Rsbuild 会相对于项目根目录解析 alias 值。请使用 `'./src'`，而不是 `path.resolve(__dirname, '../src')`。相对路径写法更简洁，并且能避免 ESM 配置中 `__dirname` 带来的问题。
:::

### 4. 转换常见的 Vite 模式

| Vite 模式                 | Rsbuild 等价方案                                 |
| ------------------------- | ------------------------------------------------ |
| `resolve.alias`           | `rsbuildFinal` 中的 `resolve.alias`              |
| `plugins: [react()]`      | 由 framework 包自动配置                          |
| `css.preprocessorOptions` | `@rsbuild/plugin-sass` 或 `@rsbuild/plugin-less` |
| `define`                  | `source.define`                                  |
| `server.proxy`            | `server.proxy`                                   |
| `build.target`            | `output.target`                                  |

:::tip Vite plugins are not compatible
Vite plugin 无法与 Rsbuild 一起使用。请在 [Rsbuild plugin 列表](https://rsbuild.rs/plugins/list/) 中查找等价的 Rsbuild plugin。
:::

## 验证

迁移完成后，请验证：

1. `npx storybook dev` 能够无错误启动
2. 所有 stories 都能正确渲染
3. HMR 正常工作（编辑某个组件，能看到它更新）
4. `npx storybook build` 能够成功完成
5. addon 功能正常（尤其是 docs、controls、actions）

## 调试

启用 Rsbuild 调试模式以检查生成的配置：

```bash
DEBUG=rsbuild storybook dev
```

查看 CLI 输出，确认 Rsbuild 和 Rspack 配置文件被写入的位置。
